## What v0.0 does

Shadow mode only (02 §1, CAP §4.7):
- It polls ServiceNow (`sync.poll.<table>` under a DB lease), deduplicates, pre-classifies and classifies each new incident through the redacting LLM boundary, and routes it.
- It records what it *would* have proposed (`shadow_records`), and nothing is sent.
- The admin UI shows approvals, cases, grants and shadow stats.
- `doctor` checks the deployment, and `replay` shows any trace end to end.

## Known limitations

The full list is in [BACKLOG.md](../BACKLOG.md). These matter for a v0.0 pilot:

- **Smoke calibration can't route.** `calibrated_score` is the Wilson lower bound and needs n ≥ 10 (ADR-0002). A perfect 12/12 scores 0.758, below `min_score` 0.80. With a smoke-grade table, every shadow case safe-defaults as `low-calibrated-score`. Agreement is still measured, because a safe default keeps the LLM's classification. The holdout grade (v0.1) or the ADR-0003 thresholds change this.
- BL-018: a mismatched calibration fails startup instead of loading empty. `doctor` reports it.
- BL-023 / BL-030: real-IdP login and the doctor's ServiceNow heuristics are verified against fakes only.
- BL-028: `proposals.expire` and `retention.sweep` aren't scheduled yet.
