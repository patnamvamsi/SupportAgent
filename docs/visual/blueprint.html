Design blueprint · spec frozen for v0.0

An application support analyst that proposes, and a database that decides what executes.

SupportAgent is a deterministic support pipeline with LLM slots. It triages ServiceNow incidents and alerts, runs bounded root-cause checks, drafts communications, and proposes actions. State-changing and customer-facing actions execute only through a database-enforced approval path.

The LLM decides content. Code decides control.

The LLM fills typed slots: a classification label, a severity, a summary, a hypothesis ID. Routing, tiers, budgets, approval and idempotency are deterministic code plus reviewed config. These six invariants are the only guarantees the product makes, and each one has CI tests on both database engines.

INV-01 · Gate

Nothing executes without one valid authorization

A single-use, hash-bound approval; an approved literal-scope grant (internal kinds only); or an approved comms plan (customer comms only). Enforced by DB triggers.

INV-02 · Dedup

One unresolved case per fingerprint

A partial unique index plus an upsert. Holds under concurrency and while a human owns the case. Human-filed tickets are never merged.

INV-03 · Trace

Every decision is an event

Every side effect, LLM call, tool call and routing decision is an append-only events row with a trace ID. Any case is replayable.

INV-04 · Idempotency

Retries are effectively-once

At-least-once delivery with unique outbox keys and read-before-write reconciliation against the target. Zero double-sends is measured in a soak test.

INV-05 · Safe default

Failure routes to a human

An LLM timeout, garbage output, classifier conflict or tool failure ends in the human queue with zero unapproved side effects. No crash.

INV-06 · Redaction

Flagged secrets never reach a provider

Redaction runs inside the LLM client, so no call site can skip it. Canary tests prove the wiring; detector recall is measured separately.

How a ticket moves through the system

Loop A (triage) is linear: no LLM branching. Every step either hands off to the next or drops to a safe default. Loop B (RCA) is the only free-running loop, and it is budgeted.

Where redaction lives

The trust chain

Every action kind has a tier, assigned at registration and never inferred at runtime. The tier decides which authorization paths exist for that kind.

T0

Read and analyze

Log reads, job status, RCA, drafting, case-memory retrieval.

Autonomous, traced, budgeted.

T1

Internal, low blast radius

work_note, enrich_page, watch_list_add_internal.

Allowed after the customer admin approves the default grants at setup.

T2

State-changing or customer-facing

Job re-runs, ticket updates, customer_comment, customer email.

Always gated. Customer-facing kinds are never grant-authorized.

T3

Self-modification

Learned runbooks, KB articles, prompt patches.

Gated, eval-gated on a disjoint holdout, versioned, one-command rollback.

Three ways into the outbox, and what the trigger refuses

Proposal state

Paging is enrich-only in v0.x. The customer's own monitoring pages people. enrich_page attaches context to an existing page. create_page exists only so the trigger can forbid it, and doctor refuses to triage a service that has no external paging integration.

Root cause analysis: a plan of checks, not a chat

A runbook is the plan when one matches. Otherwise the LLM may only pick hypothesis IDs from a fixed taxonomy, and each needs a registered probe. Evidence checks are CEL expressions compiled in CI, never Python strings.

reduce() condition, in orderOutcome
Two passing steps whose hypotheses exclude each otherINCONCLUSIVE
At least one passing step, no declared conflictSUPPORTED
All steps ran, none passedCONSISTENT_UNCONFIRMED
Budget exhausted, a tool failed, plan incompleteINCONCLUSIVE

Budgets and guards

  • Lite: ≤ 5 tool calls, ≤ 3k tokens, ≤ 3 hypotheses. Deep: ≤ 25 calls (provisional).
  • Each claim gets an entailment check: supports, contradicts or unknown. Anything but supports is tagged speculation.
  • A hypothesis can only be SUPPORTED by a registered tool. No change feed means no "recent change" support.
  • During a change freeze, the recent-change prior is zeroed and logged.

Case lifecycle and human takeover

ServiceNow is polled with an overlap window, and changes are read from sys_audit history with their actor. Only a human actor counts as takeover; assignment rules and other automation users are excluded by a list confirmed at onboarding.

Data model

Every table carries tenant_id from day one. Amber marks where an invariant is enforced in the schema. Triggers ship in both SQLite and PL/pgSQL dialects.

Retention is per-tenant config. Raw payloads are encrypted with a per-tenant key, so deleting a tenant destroys the key and leaves backups unreadable.

Roadmap

Twenty-four weeks for 2–3 engineers. Every numeric threshold is provisional until the v0.0 shadow run on the partner's real tickets sets it.

ReleaseWeeksExit story
v0.01–4Full trust chain on ServiceNow with OIDC identity. INV-01..06 green on both engines against the partner's real tickets. A shadow run on their last 50 incidents sets the provisional thresholds.
v0.15–12Triage, gated comms, RCA-lite, case memory, takeover, storm handling. Quality gates pass on a 150–250-case holdout; the shadow promotion gate passes on the lower bound.
v0.213–18An evidenced Airflow re-run executes under a customer-approved grant; a runbook is distilled and holdout-gated; assisted mode runs with a control group.
v1.019–24The value story: treatment-vs-control MTTA, time-to-first-update and MTTR deltas with confidence intervals, plus a full audit report from any trace.

Dependencies outside engineering

Partner incident history

≥6 months of tickets, alerts, logs and resolutions. The request goes out on day 0. Fallback: live shadow traffic, then a second partner.

Assisted-mode decision

The value number needs the partner to switch on a treatment set. That is a commercial milestone, agreed during v0.1.

External paging

Every catalog service needs a pager integration before triage starts, because the agent never creates pages.
