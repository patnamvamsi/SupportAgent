## WP-005 Gate schema and INV-01 triggers

- **Spec refs:** ARCH §6.2, §6.3 (tables), §12.2; 03 §2.3, §5; 01 §6 (`AuthorizationDenied` mapping).
- **Deliverables:** migration `0003_gate.py` (both dialects; kind literals generated from `domain.kinds`), `adapters/db/repos/{proposals,approvals,grants,outbox,comms_plans,comms}.py`, `adapters/db/errors.py` (maps `INV-01:` messages to `AuthorizationDenied.code`), `app/gate.py` (`GateService.submit / approve / reject / expire_due`).
- **Behaviour:**
  - `submit(case_id, spec, trace)`: validate `spec.kind` is executable and `spec.target.service` exists in the catalog (else `DomainValidationError`, logged and dropped per ARCH §4 "propose" row). Compute `payload_hash`. Insert the proposal as `proposed`. Look for an approved grant matching `(kind, scope)` exactly. If one exists and the kind is not customer-facing, transition to `approved` (grant path, no approval row) and return. Otherwise transition to `pending_approval` with `expires_ts = now + ttl`. Emit a `gate` event either way.
  - `approve(proposal_id, approver_id, seen_hash, reason)`: in one UoW, CAS `pending_approval → approved` (else `ConcurrencyConflict`); `seen_hash ≠ proposal.payload_hash` → `AuthorizationDenied("stale")`; insert the approval (the trigger blocks self-approval). Then call `OutboxExecutor.enqueue(...)` in the **same UoW**. Emit a `gate` event.
  - `expire_due(now)`: every `pending_approval` row with `expires_ts ≤ now` moves to `expired`, with one `gate` event per row.
- **Tests first:** every INV-01 test ID in 04 §5 marked WP-005, plus `test_gate_submit_drops_unknown_service_target`, `test_gate_submit_grant_path_auto_approves_internal_kind`, `test_gate_submit_customer_kind_never_grant_path`, `test_gate_approve_stale_hash_conflict`, `test_gate_approve_concurrent_second_fails`, `test_gate_expire_due_marks_expired`.
- **Patterns:** Command, State, Unit of Work, Repository.
- **DoD:** all INV-01 tests are green on SQLite **and** Postgres. Every trigger is exercised at least once per dialect.

## WP-006 Outbox executor and reconciliation (INV-04)

- **Spec refs:** ARCH §6.2 (effectively-once), 01 §7.4, §7.5.
- **Deliverables:** `app/outbox.py` (`OutboxExecutor.enqueue(...)`, `.run_once(now)`), `adapters/db/repos/outbox.py` (`claim_next` with CAS), an action handler registry `app/handlers.py` (`HANDLERS: Mapping[ActionKind, Handler]`; v0.0: `work_note`, `customer_comment`, `ticket_update`), worker job `outbox.execute` (02 §7).
- **Behaviour:** `run_once`:
  1. Claim the next due row (`pending`, `next_attempt_ts ≤ now`) via CAS to `claimed`.
  2. Re-hash `payload_json`; on mismatch, `mark_failed(..., retry_at=None)` and emit `executor_hash_mismatch`.
  3. Reconcile: `sink.find_marker(...)` (journal kinds) or read-compare (field updates). If found, `mark_done(ref)` and emit `send` with `reconciled=true`.
  4. Otherwise execute the handler, which appends the `[sa:<key>]` marker line, then `mark_done`.
  5. On `ExternalServiceError(retryable=True)`, `attempts += 1` and `next_attempt_ts = now + backoff(attempts)`; after 5 attempts, `failed` plus a `send` error event and a safe-default notice on the case. A non-retryable error fails immediately.
  Every claim, send and failure emits a `send` event.
- **Tests first:** `test_idempotent_replay`, `test_executor_rehash_mismatch_aborts`, `test_executor_reconciles_existing_marker`, `test_executor_retries_retryable_with_backoff`, `test_executor_fails_non_retryable_immediately`, `test_executor_gives_up_after_5_attempts`, `test_executor_concurrent_claims_exclusive` (two executors, one row → one send), `test_marker_appended_to_journal_text`.
- **DoD:** `FakeServiceNow` sees exactly one journal entry per approved action across 100 randomized crash points (property test with crash injection between steps 4 and 5).

- **Deliverables:** migration `0005_shadow.py`, `app/shadow.py` (`ShadowRunner.run(evt)`: the same `Classifier` and `build_action_specs`, writes `shadow_records`, **no gate submit, no outbox**), `app/stats.py` (`StatsService.report(window, mode)`: agreement rate + Wilson LB, alert→first-proposal p50/p95, safe-default rate by reason, conflict and abstain rates), `entrypoints/cli/{stats,shadow_import}.py`.

- **DoD:** a shadow run over 50 fixture incidents produces a report, and the report's numbers match a hand-computed golden file.
